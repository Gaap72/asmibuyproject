## Comportamiento antes y después
| Caso | Antes | Después |
| --- | --- | --- |
| Error sin datos previos | `console.error`; estado vacío falso «No se encontraron insumos…» | Bloque de error con mensaje y «Reintentar»; no aparece el estado vacío |
| Error con datos previos | Datos viejos sin ningún indicio | Datos previos se conservan; el bloque de error añade «Se muestran los datos de la última consulta correcta (hh:mm).» |
| Recarga al volver a la pestaña (`visibilitychange`, `focus`) | Error silencioso | Mismo manejo; si ya hay una consulta en curso no lanza otra |
| Reintento | No existía | «Reintentar» llama a `recargarAvisos()`; en éxito el error desaparece y se muestra «Actualizado hh:mm» |

Mensajes: `status 0` → «No se pudo conectar con el servidor.»; 401 o 403 → «Tu sesión no permite consultar los avisos.»; otros → «No se pudieron consultar los avisos.».

## Prueba manual local (QA-LOCAL-2026-11-24)
Entorno: PostgreSQL 18.4 local, API y frontend en localhost, Zen Browser (versión sin número registrado, «última versión» según la persona; no se usó Chrome ni Edge). Ejecutó la persona del navegador; el asistente detuvo y levantó la API.

| Caso | Observado | Resultado |
| --- | --- | --- |
| a) Con sesión abierta, API detenida y Actualizar | Bloque rojo con error y «Reintentar», datos previos en pantalla con la hora y sin el texto «No se encontraron insumos». La persona confirmó que cumple todo lo esperado; no se anotó cuál de los dos textos de error salió | cumple |
| b) Entrar en Avisos con la API detenida, sin recargar | Bloque rojo con «No se pudieron consultar los avisos.», sin el estado vacío falso | cumple |
| c) Levantar la API y pulsar Reintentar | El error desaparece y vuelve el estado con los datos | cumple |
| 360 px, con el error visible | El bloque y el botón «Reintentar» se ven completos, sin desbordamiento horizontal | cumple |

Observación: con el proxy de `ng serve`, una API caída llega como error de servidor (5xx) y no como status 0, así que sale «No se pudieron consultar los avisos.». El texto «No se pudo conectar con el servidor.» solo aparece si el navegador no recibe respuesta alguna y no se ejercitó. Tampoco se probaron 401 o 403 de forma deliberada: con una sesión revocada salió «Tu sesión no permite consultar los avisos.» (ver QA-LOCAL, CW-01).
