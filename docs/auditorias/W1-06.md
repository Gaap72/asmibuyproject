Diferencias con la guía y hallazgos:
- **Comando de build de la API.** El de la guía, `npm ci && npm run build:backend`, falla en Render: con `NODE_ENV=production`, `npm ci` omite las dependencias de desarrollo y `tsc` no encuentra `typescript` ni `@types/node` (errores TS2307 y TS2591). Se usa `npm ci --include=dev && npm run build:backend`. No se cambió código.
- **Corte de unos 3 minutos (19:59 a 20:02 CST).** Al quitar el Root Directory, la versión anterior (`b9f4211`) no encontraba `dist/index.js` y la API quedó caída hasta el primer build correcto.
- **TLS de la base validado.** Se cargó `DB_SSL_CA` con el certificado PEM público de Supabase (`prod-ca-2021.crt`, 23 líneas con saltos reales) y se activó `DB_SSL_REJECT_UNAUTHORIZED=true`. Tras el redespliegue (`dep-dc3rdsu1egvs73ehjcag`), `/api/v1/health` confirma la conexión TLS validada a Supabase.
- `CORS_ORIGIN` y `PORT` se conservan por decisión del integrante 3. El código usa `ALLOWED_ORIGINS` primero.
- `SESSION_SECRET` ya existía; no se sabe si se generó con el procedimiento de la guía.

Pendiente de este despliegue: versión de PostgreSQL de Supabase y migración 007 (C-1 a C-4); cookie `asmibuy_session`, login, `/auth/me`, logout y CSRF 403 en Chrome o Edge (A6 a A8, integrante 2); cuentas de QA; teléfonos (CW-17); restauración (CW-20).
